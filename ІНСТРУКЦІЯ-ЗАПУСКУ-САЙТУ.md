# Запуск сайту «Електронний розклад» в Інтернеті

**Покрокова інструкція для людини без досвіду програмування.**

Що ви отримаєте в кінці:
* власний сайт виду `https://ВАШ_ЛОГІН.github.io/rozklad-mirror/site/`;
* розклад усього університету (**усі групи та всі викладачі**, що є
  в електронному розкладі), доступний цілодобово — **навіть коли сервер
  університету вимкнений**;
* автоматичне оновлення даних кожні 2 години вдень — без вашої участі
  і без вашого комп'ютера;
* вартість — **0 грн**, реєстрації — лише GitHub (безкоштовна).

Час виконання: приблизно **30 хвилин** (плюс ~1,5 години очікування першої
синхронізації, яка йде сама).

Що знадобиться: електронна пошта, доступ в інтернет, цей архів.

---

## Крок 1. Реєстрація на GitHub (5 хвилин)

GitHub — це безкоштовний сервіс, де житимуть файли сайту та дані розкладу.

1. Відкрийте у браузері адресу **https://github.com**.
2. Натисніть **Sign up** (Зареєструватися).
3. Введіть свою електронну пошту → **Continue**.
4. Придумайте пароль → **Continue**.
5. Придумайте логін (**username**) — лише латинські літери, цифри, дефіс,
   наприклад `kpo-udu`. **Запишіть його** — він буде в адресі сайту.
6. Пройдіть перевірку «я не робот» і натисніть **Create account**.
7. GitHub надішле на пошту листа з кодом — введіть його.

Готово: у вас є акаунт GitHub.

---

## Крок 2. Створення сховища (репозиторію) (2 хвилини)

Репозиторій — це тека на GitHub, де лежатимуть усі файли проєкту.

1. Увійшовши на GitHub, натисніть зелену кнопку **New** (або «+» угорі
   праворуч → **New repository**).
2. У полі **Repository name** введіть: `rozklad-mirror`
3. Лишіть позначку **Public** (публічний — це потрібно, щоб сайт і дані
   були доступні без пароля; сам розклад і так публічний на сайті
   університету).
4. Галочку **Add a README file** ставити НЕ треба.
5. Натисніть **Create repository**.

Відкриється сторінка вашого порожнього репозиторія
`github.com/ВАШ_ЛОГІН/rozklad-mirror`.

---

## Крок 3. Завантаження файлів проєкту (10 хвилин)

Файлів у проєкті багато (понад 2000 — це дані розкладу), тому через
вебсторінку їх не завантажити (GitHub приймає до 100 файлів за раз).
Найпростіший шлях — безкоштовна програма **GitHub Desktop**.

### 3.1. Встановіть GitHub Desktop

1. Відкрийте **https://desktop.github.com** і завантажте програму
   (Windows або Mac).
2. Встановіть її як звичайну програму.
3. При першому запуску натисніть **Sign in to GitHub.com** — відкриється
   браузер, підтвердьте вхід у свій акаунт.

### 3.2. Скачайте порожній репозиторій на комп'ютер

1. У GitHub Desktop: **File → Clone repository…**
2. У списку виберіть `ВАШ_ЛОГІН/rozklad-mirror`.
3. Нижче в полі **Local path** оберіть теку, де він лежатиме на комп'ютері
   (наприклад, «Документи»). Запам'ятайте це місце.
4. Натисніть **Clone**.

### 3.3. Скопіюйте файли проєкту в теку репозиторія

1. **Розпакуйте** архів `Дзеркало-розкладу-УДУ.zip` (двічі клацнути /
   «Extract all»).
2. Відкрийте розпаковану теку `rozklad-cloud` і **виділіть усе її вміст**
   (Ctrl+A / Cmd+A): теки `data`, `site`, `sync`, `worker`, `.github`
   та файли `README.md`, `ІНСТРУКЦІЯ-ЗАПУСКУ-САЙТУ.md`.

   > ⚠️ **Дуже важливо — тека `.github`!** Вона може бути невидимою.
   > Саме вона відповідає за автоматичне оновлення розкладу.
   > * **Windows:** у Провіднику вкладка **Вид → Показати → Приховані
   >   елементи** (галочка), тоді `.github` стане видно.
   > * **Mac:** у Finder натисніть **Cmd + Shift + .** (крапка) —
   >   приховані файли з'являться.
   >
   > Переконайтеся, що `.github` потрапила в копію.

3. Скопіюйте все виділене **в теку репозиторія** (ту, яку ви обрали
   у пункті 3.2; поруч з'явиться і файл README репозиторія, якщо він є —
   його можна видалити або лишити).

### 3.4. Опублікуйте файли на GitHub

1. Відкрийте **GitHub Desktop** — він уже «побачив» нові файли: ліворуч
   буде список із ~2400 змінених файлів.
2. Унизу зліва в полі **Summary (required)** напишіть:
   `Дзеркало розкладу: старт`
3. Натисніть синю кнопку **Commit to main**.
4. Потім натисніть **Push origin** (кнопка зверху).
5. Зачекайте, доки завантаження завершиться (перший раз — кілька хвилин,
   бо файлів багато).

### 3.5. Перевірте

Відкрийте у браузері `github.com/ВАШ_ЛОГІН/rozklad-mirror` — ви маєте
побачити теки `data`, `site`, `sync`, `worker`, `.github` у репозиторії.

> Якщо вам звичніший командний рядок, замість GitHub Desktop можна
> виконати в теці `rozklad-cloud`:
> ```bash
> git init && git add -A && git commit -m "Дзеркало розкладу: старт"
> git branch -M main
> git remote add origin https://github.com/ВАШ_ЛОГІН/rozklad-mirror.git
> git push -u origin main
> ```

## Крок 4. Увімкнення автоматичного оновлення (3 хвилини + очікування)

Автооновлення вже налаштоване у файлі `.github/workflows/sync.yml` —
треба лише дозволити його запуск.

1. На сторінці репозиторія відкрийте вкладку **Actions** (вгорі).
2. Якщо GitHub показує жовту плашку з питанням — натисніть
   **«I understand my workflows, go ahead and enable them»**.
3. Ліворуч клацніть на workflow **«Синхронізація розкладу»**.
4. Праворуч з'явиться кнопка **Run workflow** — натисніть її і ще раз
   **Run workflow** у спливаючому вікні. Це **перший ручний запуск**,
   щоб не чекати розкладу.
5. Оновіть сторінку через хвилину — у списку з'явиться запуск із жовтим
   кружальцем (виконується). **Перша синхронізація триває 1–1,5 години**
   (обхід усіх ~2000 груп і викладачів університету). Це нормально;
   можна закрити вкладку й повернутися пізніше.
6. Коли кружальце стане **зеленою галочкою** — на головній сторінці
   репозиторія з'явиться новий коміт «Дзеркало розкладу:
   синхронізація …». Все працює.

Надалі синхронізація запускатиметься **сама кожні 2 години** вдень
(орієнтовно 06:00–22:00 за Києвом). Якщо сервер університету у цей момент
недоступний (блекаout) — запуск тихо пропуститься, а сайт лишиться з
останніми вдалими даними. Це і є головна властивість дзеркала.

## Крок 5. Увімкнення сайту (GitHub Pages) (3 хвилини)

1. На сторінці репозиторія відкрийте **Settings** (вкладка вгорі праворуч).
2. У меню ліворуч виберіть **Pages** (розділ «Code and automation»).
3. У розділі **Build and deployment**:
   * **Source:** оберіть **Deploy from a branch**;
   * **Branch:** оберіть **main**, поруч — **/ (root)**, натисніть **Save**.
4. Зачекайте **2–5 хвилин** і оновіть сторінку Settings → Pages — зверху
   з'явиться зелена плашка **«Your site is live at
   https://ВАШ_ЛОГІН.github.io/rozklad-mirror/»**.
5. **Сайт розкладу відкривається за адресою:**

   **https://ВАШ_ЛОГІН.github.io/rozklad-mirror/site/**

   (частина `/site/` обов'язкова — сторінка лежить у теці `site`).

6. Перевірте роботу: почніть вводити назву групи (наприклад, `43ПОцт`)
   або прізвище викладача → оберіть зі списку → має з'явитися розклад.
   У шапці сайту видно бейдж **«Дані станом на …»** — час останньої
   синхронізації.

Готово — сайт у мережі! Поширте цю адресу студентам і викладачам,
додайте її на сторінку кафедри або в Moodle.

## Крок 6. (Необов'язково) Telegram-бот

Окрім сайту, у пакеті є Telegram-бот, який читає те саме дзеркало і теж
працює під час блекаутів. Його запуск описано у файлі **README.md**
(розділ «Крок 3. Telegram-бот на Cloudflare Workers»). Це необов'язкова
частина — сайт працює й без бота.

## Що важливо знати надалі

* **Нічого підтримувати не треба.** Сайт, дані й автооновлення живуть
  на GitHub самі. Ваш комп'ютер може бути вимкнений.
* **Оновлення даних:** кожні 2 години автоматично. Примусово оновити
  можна в будь-який момент: вкладка **Actions → Синхронізація розкладу →
  Run workflow**.
* **Горизонт розкладу:** весь навчальний рік від 1 вересня + 75 днів
  уперед. Межа «котиться» сама: 1 вересня 2027 року дзеркало перейде
  на новий навчальний рік.
* **Застарілість даних:** якщо знімку понад 30 годин (наприклад, сервер
  університету довго лежав), бейдж у шапці сайту стане червоним і чесно
  попередить «знімок застарів».
* **Заміна розкладу:** сайт лише показує те, що є в офіційному
  електронному розкладі університету (nmc.udu.edu.ua). Усі зміни
  вносяться, як завжди, через відповідальних за розклад — дзеркало
  підхопить їх при наступній синхронізації.

## Типові проблеми та розв'язання

| Проблема | Розв'язання |
|---|---|
| У вкладці Actions порожньо | Ви не скопіювали теку `.github` — поверніться до кроку 3.3, увімкніть показ прихованих файлів |
| Запуск синхронізації «червоний» | Відкрийте його та гляньте лог. Найчастіша причина — сервер університету тимчасово недоступний: просто запустіть пізніше (Run workflow). Дані від цього не зникають |
| Сайт показує помилку 404 | Зачекайте 5 хвилин після кроку 5; перевірте, що в адресі в кінці є `/site/`; перевірте, що Pages увімкнено з гілки `main` / `(root)` |
| Сайт відкривається, але пише «Не вдалося завантажити дзеркало» | Перевірте, що тека `data` є в репозиторії (крок 3.5) і що перша синхронізація завершилась зеленою галочкою |
| Хочу зупинити автооновлення | Settings → Actions → General → Actions permissions → Disable actions |
